# Android: local development, signed APK and installation

Build locally using the generated Android Gradle wrapper. EAS/cloud builds, an Expo account and a Play Store account are unnecessary. Internet is needed once for npm, Android tools, Gradle and Maven dependencies; the installed release app works offline.

## Toolchain

- Node 26.13 LTS with npm; the lockfile is committed. Use `npm ci`.
- Android Studio, Android SDK command-line tools, platform-tools (`adb`) and an emulator image or USB device.
- JDK 17 (`JAVA_HOME` must point to it).
- The pinned Expo 58 / React Native 0.88.1 dependencies specify Android SDK platform **37**, Build Tools **37.0.0**, NDK **27.1.12297006**, minimum SDK **24**, target SDK **36**. Install these through SDK Manager, including side-by-side NDK and CMake if Gradle requests it. Values are derived from `node_modules/react-native/gradle/libs.versions.toml`; use that file if deliberately updating dependencies.
- Gradle wrapper **9.4.1** is generated by prebuild; no global Gradle installation is needed.

Set `ANDROID_HOME` to the SDK directory, `JAVA_HOME` to JDK 17, and add the SDK's `platform-tools` to PATH. Typical Windows SDK path: `%LOCALAPPDATA%\Android\Sdk`. Typical macOS SDK path: `~/Library/Android/sdk`. A generated `android/local.properties` may instead contain `sdk.dir` with your local SDK path. Do not commit it.

## Development

```sh
npm ci
npm run check
npx expo prebuild --platform android
npx expo run:android
```

Android Studio may open the generated `android/` directory. An Android development build uses Metro; start it using `npm start`. For a first look Expo Go may work with a matching SDK, but custom Android share intents and release behavior need a native build.

## Signing, one-time setup

Choose your final `android.package` in `app.json` before distributing. The default is `app.verdant.routine`. Change `scheme` if publishing a differently named app. Regenerate Android after configuration changes. Users can upgrade without losing data only when package ID and signing key remain the same and versionCode increases.

Create a release keystore **outside the repository**. Replace the path below with your private location. `keytool` asks for passwords interactively; avoid embedding them in a script or command history.

```sh
keytool -genkeypair -v -keystore /private/path/verdant-release.jks -alias verdant -keyalg RSA -keysize 3072 -validity 10000
```

On Windows, use a private absolute path such as `C:\Users\YOUR_NAME\Keys\verdant-release.jks`. Keep an encrypted off-device copy of the keystore and passwords. Losing the key prevents normal upgrades of existing installs.

The config plugin `plugins/withLocalRelease.cjs` installs a release signing configuration during every prebuild. It replaces the Expo template's debug signing for release and fails a release task if any required signing environment variable is missing. It never contains a signing key or password. `android/` is intentionally regenerated and ignored; the plugin is the canonical source of these native customizations.

## Build a signed release APK

macOS/Linux, from the repository root:

```sh
npx expo prebuild --platform android
export VERDANT_KEYSTORE=/private/path/verdant-release.jks
export VERDANT_KEY_ALIAS=verdant
read -s -p 'Store password: ' VERDANT_STORE_PASSWORD
export VERDANT_STORE_PASSWORD
read -s -p 'Key password: ' VERDANT_KEY_PASSWORD
export VERDANT_KEY_PASSWORD
cd android
./gradlew :app:assembleRelease
```

Windows PowerShell, from the repository root (replace the private path):

```powershell
npm ci
npx expo prebuild --platform android
$env:VERDANT_KEYSTORE = 'C:\Users\YOUR_NAME\Keys\verdant-release.jks'
$env:VERDANT_KEY_ALIAS = 'verdant'
$storeSecret = Read-Host 'Store password' -AsSecureString
$keySecret = Read-Host 'Key password' -AsSecureString
$env:VERDANT_STORE_PASSWORD = [System.Net.NetworkCredential]::new('', $storeSecret).Password
$env:VERDANT_KEY_PASSWORD = [System.Net.NetworkCredential]::new('', $keySecret).Password
Set-Location android
.\gradlew.bat :app:assembleRelease
```

Output: `android/app/build/outputs/apk/release/app-release.apk`.

These environment variables are visible to your build process. Use a trusted computer and clear them or close the terminal after the build. Do not paste secrets into a public issue, `.env`, `gradle.properties`, README, CI logs or this chat. Ignore rules are defense in depth; inspect staged changes before publishing.

To verify the signature, use the SDK Build Tools `apksigner verify --verbose --print-certs` on the APK. Check the signer against your own keystore. Confirm the build is signed with your release identity, not the Android debug certificate.

## Install and upgrade

```sh
adb devices
adb install -r android/app/build/outputs/apk/release/app-release.apk
```

Or copy the APK to your phone, open it in Files and allow installation from that source when Android requests it. Disable that permission again afterward if desired. First launch and a sample plan should work in airplane mode without Metro.

A debug build signed with the debug key cannot be upgraded by a release APK with a different key. Export data before uninstalling the debug app. Avoid uninstalling a daily-use release unless you have a verified backup.

## Version and GitHub releases

1. Increase `expo.version` and integer `android.versionCode` in `app.json`, and update `package.json` version consistently.
2. Run `npm ci`, `npm run check`, `npm run bundle:android` and the device checklist in `docs/TESTING.md`.
3. Regenerate the native project and build/sign locally using the original keystore.
4. Install over the previous release and verify existing records remain. Export and restore a backup on a test install.
5. Commit source and lockfile, tag `vX.Y.Z`, create a GitHub release manually, attach the signed APK and its SHA-256 checksum, and include changes and known limits.
6. Never attach keystores, environment files or real user backups. No publication or repository creation is performed by this source package.

The included GitHub Actions workflow checks source and Android bundling. It does not require or upload signing credentials and does not publish releases.
